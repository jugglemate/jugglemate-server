# JuggleMate Server · 二次开发文档

> 对应服务：`jugglemate-server`（Go 单体，模块 `github.com/juggleim/jugglemate-server`）
> 面向：需要修改 / 扩展后端服务的开发同学。
> API 用法见 `docs/使用说明（部署与集成）.md`；Bot/分身接口详情见根目录 `README.md`；功能清单见 `docs/功能清单.md`。

---

## 1. 技术栈

- **语言**：Go 1.25（`go.mod` 声明 `go 1.25.0`）
- **Web 框架**：gin（`github.com/gin-gonic/gin`）
- **数据库**：PostgreSQL（`lib/pq` / `pgvector`），通过 Go Agent 平台统一接入
- **缓存/队列**：Redis（`go-redis/v9`）
- **IM**：JuggleIM（`imserver-sdk-go` / `imbot-sdk-go`），HTTP API + WebSocket
- **Agent 平台**：内置 Go 版 Agent 模块（`agent/bootstrap`），承担分身/训练/会话/LLM 调用
- **对象存储**：Aliyun OSS（知识库/附件，可配）
- **前端**：`console/web`（Vue，由 `build.sh` 构建后内嵌服务）

## 3. 配置

配置文件：`conf/config.yml`（实际）/ `conf/config_example.yml`（样例，提交进仓库）。

关键字段：

| 字段 | 说明 |
|---|---|
| `port` | HTTP 监听端口（默认 `8050`） |
| `log.logPath` / `log.logName` | 日志路径与文件名 |
| `imApiDomain` | IM HTTP API 根地址（Bot 注册/建群/群成员共用） |
| `jmateBaseUrl` | 自身对外基址 |
| `agent.enabled` | 是否启用 Go Agent 平台（false 时 `/jmate/agentapi` 返回不可用） |
| `agent.postgres.dsn` | PostgreSQL 连接串 |
| `agent.redis` | Redis 地址/密码/db |
| `agent.auth.internalSecret` | JMate 转发时携带的共享密钥（Agent 原生入口只信任它） |
| `agent.security.secretKey/Salt` | 认证安全密钥 |
| `agent.knowledge.*` | 知识库向量化配置（dimension/batch/对象存储根） |
| `agent.tools.innerAPIBaseURL` | 内置工具服务地址（生产必须覆盖） |
| `agent.im.wsAddress` | Bot 常驻连接 WebSocket（须与 `imApiDomain` 同一套 IM） |

> 启动：`configures.InitConfigures()` 读取 `conf/config.yml`。

## 4. 构建与运行

```bash
# 完整构建（含控制台前端），产出 ./build/jchat-ai
./build.sh

# 仅构建后端二进制（不重建前端）
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o ./jchat-ai main.go

# 本地直接跑（开发期）
go run main.go

# 运行（确保 conf/config.yml 已配好 PG/Redis/IM）
./jchat-ai
```

- 服务监听 `:${port}`（默认 8050）。
- 控制台前端由 `console.LoadConsoleWeb` 内嵌服务；上传的静态资源（头像等）暴露在 `GET /static`（映射到 `./data`）。
- 优雅退出：监听 `SIGINT/SIGTERM/SIGQUIT`。

## 5. 目录结构与分层

```
main.go                 # 入口：配置→日志→Agent 模块→注入客服域能力→路由→ticker→运行
routers/router.go       # 全部 HTTP 路由注册（/jmate、/jmate/console、webhooks、CORS）
apis/                   # HTTP 处理器（handler）：user/customer/ticket/seats/message/telegram/juggleim/whatsapp/console_stats/validate
services/               # 业务逻辑层（*service.go）：ticket/customer/inbox/agent/csat/channel/webhook...
storages/               # 存储层（models / dbs）：表模型 + DB 访问
commons/                # 公共：configures / dbcommons / logs / errs / responses / agentclient
agent/                  # Go Agent 平台（bootstrap / 分身 / 训练 / Session / LLM）
console/                # 管理控制台：apis（用户/Inbox CRUD）+ services + web（前端）
conf/                   # 配置
data/                   # 运行时数据（上传文件、知识库对象存储根）
docs/                   # 各类 API/设计文档
openspec/               # 变更提案（changes/ + specs/），按变更组织
```

---

## 6. 路由分组（权威来源 `routers/router.go`）

| 前缀 | 内容 | 中间件 |
|---|---|---|
| `/jim/*` | 分身 AI 原生接口（add/update/remove/mybots/materials/training/jobs/versions/evaluations） | Agent 平台注册 |
| `/jmate/*`（公开） | webhooks：telegram / juggleim / whatsapp(verify+post) / message | 无 |
| `/jmate/*`（鉴权） | user/login,user/register；customers/*；tickets/*；seats/list | `apis.Validate` |
| `/jmate/console/*` | 用户 CRUD、Inbox CRUD（4 渠道）、inbox 成员、inbox-agent 绑定、统计 | `consoleApis.Validate` |
| `/jmate/agentapi/*` | Go Agent 平台向控制台注册的本地接口（会话协同/托管/切换等） | Agent 模块 |
| `/botmsgs/msgcallback` | IM Server 消息回调（Node 转发入口 `/botmsgs/forward`） | 无 |

## 7. 如何新增一个业务接口（以客服域为例）

1. **Handler**：在 `apis/` 新增/扩展文件，写 `func Xxx(ctx *gin.Context)`（用 `responses.SuccessHttpResp` / `ErrorHttpResp` 返回统一结构 `{code,msg,data}`）。
2. **Service**：在 `services/` 写业务逻辑（如 `ticketservice.go`）。
3. **Storage**：在 `storages/` 加表模型与 DB 方法（沿用 `commons/dbcommons`）。
4. **路由**：在 `routers/router.go` 的对应 group 注册（公开放 `publicGroup`，需登录放 `group`，控制台放 `RouteConsole`）。
5. **鉴权**：需登录接口走 `apis.Validate`（读 `Authorization`）；控制台走 `consoleApis.Validate`。
6. **测试**：同包加 `*_test.go`（项目已有大量 handler/service 测试，参考 `ticket_test.go`）。

## 8. 客服域与 Agent 平台的装配

`main.go` 通过**依赖注入**把客服域能力挂到 Agent 平台，避免 Agent 模块直接依赖客服 `services` 包：

- `agentModule.SetUnbindInboxAgent(services.UnbindInboxAgent)` —— 删除 Agent 时清理关联 Inbox 与 Ticket 群里的 Bot。
- `agentModule.SetHumanHandoff(services.SwitchTicketToHuman)` —— 转人工时把坐席拉进群、移出 Bot。
- `agentModule.SetMarkHumanTakeover(services.MarkHumanTakeover)` —— 持久化「转人工」事实与事件流水。

> 改这些装配点时，注意必须在 `dbcommons.UsePostgres(postgres)` **之后**调用（实现依赖共享 PG 连接）。

---

## 9. 后台任务

- `services.StartAutoCloseTicker(ctx, cfg)`：按 `last_user_msg_at` 阈值自动关闭工单并发 `jgm:csat` 评价邀请卡（走 IM REST API，不依赖 Bot 长连接）。
- 仅在 `agentModule.Enabled()` 时启动；Shutdown 时显式 `StopAutoCloseTicker()`，避免 ticker 在 IM/DB 关闭后跑导致 panic。
- 新增定时任务建议沿用此 ticker 模式或引入 cron 框架，集中管理生命周期。

---

## 10. 数据库与迁移

- 统一 PostgreSQL，由 Agent 平台初始化并 `dbcommons.UsePostgres(postgres)` 注入。
- 表模型在 `storages/models/`，访问在 `storages/dbs/`（`commons/dbcommons` 提供通用能力）。
- 涉及表结构变更：参考既有 migration 组织方式（见 `server-gap-analysis.md` 中提到的 `commons/dbcommons/sqls/`），注意与 `storages/models` 对齐。

## 12. 已知约束 / 注意

- **Session 与 webhook 联动**：客户发起时由 webhook 触发自动 `CreateSession` 注入默认 Agent（已装配）；历史版本曾缺，现已补。
- **群成员粒度**：建群时按策略拉入成员（见 `server-gap-analysis.md` 的 `createGroupForCustomer`）。
- **状态机**：工单含 `pending/processing/resolved/reopened/closed`（closed 为 DB 隐藏终态，前端不可见）。
- **CORS**：当前 `corsHandler` 为 `*` 全开，生产应收紧。
- **配置密钥**：`internalSecret` / `secretKey` 等为示例值，生产必须覆盖。
